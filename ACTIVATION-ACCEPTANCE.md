# Acceptance checks after email/dashboard work resumes

This is a checklist, not authorization to create accounts, change settings, send mail, or deploy. Those actions remain paused. Use controlled test accounts and an isolated test database where possible. Do not bypass production submission/report limits or email consent.

1. **Sender** — verify the exact Resend DNS records; configure Supabase SMTP and permitted site/redirect URLs; store email and scheduler credentials in their private settings. Keep email confirmation required. Do not set readiness flags before successful delivery tests.
2. **Account** — create and confirm the initial administrator account; confirm a different unverified account cannot submit, RSVP, or moderate. Check confirmation and recovery links return to the intended page, and a recovery link exposes the new-password form immediately.
3. **Plans** — save a current imported event and RSVP; confirm the account list reflects the selected status, removal works, and the organizer ticket link remains the source of admission. Verify a retired or confirmed-hidden event is unavailable for new saves.
4. **Locations and consent** — add one state-wide and one exact city/state preference. Enabling alerts must be a separate action. Saving unchanged enabled preferences must not move the consent cutoff. Existing members must be able to opt out even when the sender is unavailable.
5. **New-only matching** — a genuinely new eligible event after location creation and consent should queue; existing historical listings must not cause a backlog. Nonmatching states/cities must not send. Confirm only the controlled test recipient receives mail.
6. **Retries and withdrawal** — prove an identical uncertain attempt retains its batch identity; a changed recipient/event or partially withdrawn batch is suppressed as documented. Confirm no alert is sent for a confirmed-hidden event. Do not use a real-member mailing as a test.
7. **Unsubscribe** — visiting a link alone must not change preferences. Explicit confirmation must disable alerts, including while signed out. Verify the next scheduled run sends nothing to that opted-out test member.
8. **Flyers** — reject missing, invalid, or oversized uploads; keep pending flyers private. A valid submission should show success, clear its form once, and appear in the organizer's submission list. A failed request should retain the form for correction.
9. **Trust and moderation** — exercise first-four distinct human approvals and a fifth eligible automatic publication. Respect the three-per-day limit in production, or use isolated fixtures for multi-day checks. Verify source/flyer evidence attestation, report review, hidden submission status, suspended publishing, and cross-member privacy.
10. **Administrator transfer** — use verified controlled accounts; reject an unverified replacement and ensure the former administrator loses moderation access after a successful transfer. Obtain explicit approval before changing the real site's administrator.
11. **Scheduling** — manually run the installed scheduler only after the matching private secret and sender are configured; inspect aggregate success/failure without printing credentials or subscriber details. GitHub schedules may be delayed, so do not promise exact 15-minute delivery.
12. **Search** — confirm both owner-dashboard sitemap submissions show success; inspect a current event URL and state page. Google/Bing indexing or ranking is not an acceptance guarantee. Member-submitted static search pages remain a separate proposal.
