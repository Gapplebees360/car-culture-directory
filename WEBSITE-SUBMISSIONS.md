# Member-submitted event websites

Verified registered members can submit a public HTTPS website in Your Garage. Directly submitted individual events still require flyers and retain their existing approval rules. The owner explicitly approved original website pages as evidence for crawler imports, and automatic enrollment of sites that pass inspection.

The inspector checks at most three same-origin pages plus robots.txt, extracts explicit upcoming US event records from supported JSON-LD, rejects unrelated/cancelled/virtual/incomplete records, and compares potential duplicates against existing listings. Distinct same-day events on a shared calendar URL receive distinct stable identities. Repeated occurrences retain separate dates. Existing listings take priority; the website worker never overwrites a different source's event.

Positively automotive sites can enter recurring monitoring even when their layout has no supported structured events. That does not create invented dates. A business being automotive does not qualify every event it hosts: the event itself must provide automotive evidence. Classification and structured-data checks do not prove organizer legitimacy; members can flag imports and administrators can pause a source.

Initial implementation limits: JSON-LD only, 100 new events per inspection, one recurring entry URL per canonical host, bounded same-origin discovery, 1 MB uncompressed responses, 10-second request limits and a 60-second inspection budget. Robots rules are respected. Private/reserved network targets are blocked with per-request DNS validation and TLS connections pinned to validated public IPs. Cross-origin redirects, including a www alias, require resubmitting the destination's canonical URL. JavaScript-only calendars, login-only pages, unsupported HTML calendars, blocked sites, and additional separate calendars may require a specialized adapter. This feature does not promise complete discovery on every site.

Queued submissions are inspected by `.github/workflows/website-inspection.yml` roughly every 30 minutes; GitHub schedules can be delayed. Enrolled sources are due for reinspection daily. The regular daily directory refresh also processes the queue. Private inspection leases expire safely and are bounded. Reports show accepted, duplicate and rejected counts, source enrollment, and supported-format limitations without claiming a failed request succeeded.

The worker authenticates with short-lived, signed GitHub OIDC tokens. The Edge Function verifies signature, issuer, audience, immutable repository identity, main branch, allowed workflow and event type before calling service-only claim/finish/export RPCs. A full Supabase service-role key is not placed in GitHub, the browser, submitted website requests, or public files. No new shared secret is needed for website inspection.

The worker exports only approved events linked to enabled, nonsuspended website sources and merges them with existing imported feeds. Private submitter identity, lease tokens and full reports are not exported into the public site. Failed inspection preserves prior accepted source events; source suspension and confirmed event reports are respected. Absent records on a partially inspected site are not treated as proof of cancellation; organizer updates and community reports remain necessary.

Release requires the approved database proposal, matching Edge Function including `website-worker-auth.mjs`, frontend, and workflow changes together. Email signup remains a separate dependency: the interface requires a verified account and does not bypass the paused signup/email activation.
